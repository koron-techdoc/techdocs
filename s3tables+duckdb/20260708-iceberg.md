## duckdb-iceberg のコード読み

キーワード `s3_tables` が基点。
`ATTACH` する際に `ENDPOINT_TYPE s3_tables` と指定することから。

`IcebergEndpointType::AWS_S3TABLES` が内部的な識別子。
他に [`IcebergEndpointType::AWS_GLUE`](https://aws.amazon.com/jp/glue/) が利用できそう。


```c
enum class IcebergEndpointType : uint8_t { AWS_S3TABLES, AWS_GLUE, INVALID };
```

`AWS_S3TABLES` の利用箇所は `src/catalog/rest/iceberg_catalog.cpp` に集中

- config を設定・構成する
- 名前からエンドポイントを決定する
- `ATTACH` の実装

S3 Tables向けに、サポート(アクセス)するAWSのエンドポイント一覧が、コードから抽出できた。
順序は整理のために並べ替えた。

```
GET     /v1/{prefix}/namespaces
POST    /v1/{prefix}/namespaces

HEAD    /v1/{prefix}/namespaces/{namespace}
GET     /v1/{prefix}/namespaces/{namespace}
DELETE  /v1/{prefix}/namespaces/{namespace}

GET     /v1/{prefix}/namespaces/{namespace}/tables
POST    /v1/{prefix}/namespaces/{namespace}/tables

HEAD    /v1/{prefix}/namespaces/{namespace}/tables/{table}
GET     /v1/{prefix}/namespaces/{namespace}/tables/{table}
POST    /v1/{prefix}/namespaces/{namespace}/tables/{table}
DELETE  /v1/{prefix}/namespaces/{namespace}/tables/{table}

POST    /v1/{prefix}/tables/rename
```

`/v1/{prefix}/namespaces/{namespace}/tables/{table}` が Apache Iceberg のメタデータにアクセスするRESTらしい。

解説: <https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/s3-tables-integrating-open-source.html>

`ATTACH` における手続きの概要

-   一般オプションの解釈
-   `ENDPOINT_TYPE` の解釈とAWS Catalog オプションの設定
-   認証方法の解釈
-   認証用ヘッダーの作成
-   設定のチェック: 未解釈のオプションがあったら例外を投げる
-   カタログオブジェクトの作成

`IcebergCatalog` にある公開スタティックメソッド

-   Attach
-   GetHTTPSecret
-   GetIcebergSecret
-   GetOnlyMergeOnReadSupportedErrorMessage
-   GetStorageSecret
-   SetAWSCatalogOptions

DuckDB により RDBMS としての「カタログ」が要求される。
`IcebergCatalog` は、それをAWS S3 Tables ならびに GLUE 用に実装したもの。

REST Catalogなる概念が。
参考: [Iceberg REST Catalogを理解する](https://zenn.dev/ruriopcode/articles/1688d852ddc75a)

Apache Iceberg による REST Catalog の仕様: <https://iceberg.apache.org/rest-catalog-spec/>

## ここまでのまとめ

duckdb-iceberg のソースコードを眺めて、AWS S3 Tablesの仕組みへの学習を進めた。

要は、静的なファイル (parquet) ≒ テーブルを如何にして RDBMS として成立させるかという話らしい。
静的なファイルに足りないのは、テーブル以外のRDBMSとしてのメタデータで、
それを Apache Iceberg が主導する REST Catalog という API で補ったのが AWS S3 Tables となる。

- ARNでデータベースインタンスを指定
- REST Catalog でカタログ情報を取得
- クエリを各テーブル≒parquetファイルへの読み取りに読み替え実行

ということを duckdb-iceberg が、関連する別の拡張と協調して、実行している。

- httpfs - HTTPアクセス
- aws - AWSアクセス(httpfs 利用)
- parquet - Parquetファイルの解釈
